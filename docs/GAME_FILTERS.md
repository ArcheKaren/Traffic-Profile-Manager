# Игровые фильтры

Игровой фильтр — это переносимый набор сетевых правил для одной игры или
лаунчера. Он может содержать:

- временные сопоставления имён и IP для Windows `hosts`;
- домены, которые добавляются к активной стратегии zapret2;
- IP-адреса и CIDR-диапазоны для активной стратегии;
- отдельные исключения доменов и IP;
- необязательную обработку игровых TCP/UDP-протоколов на заданных портах.

Фильтры не привязаны к конкретному исполняемому файлу. Транспортный слой
ограничивается IP-набором выбранной игры и первыми пакетами соединения.
Менеджер обнаруживает все корректные подпапки в `config\game-filters` при
каждом открытии меню.

## Управление

Откройте `Manager.bat` и выберите **Game filters**.

- `[ ]` — фильтр выключен;
- `[x]` — фильтр включён;
- `[!]` — в файлах есть ошибка, такой фильтр нельзя включить;
- номер фильтра переключает его состояние;
- `U` настраивает универсальный игровой TCP/UDP-транспорт для стандартных
  стратегий;
- `C` создаёт новый пользовательский фильтр;
- `T` настраивает транспортный режим, порты и пресет;
- `E` открывает папку выбранного фильтра;
- `V` проверяет все игровые фильтры.

Список включённых фильтров хранится локально в
`state\enabled-game-filters.txt`. В чистую релизную сборку это состояние не
переносится.

Созданные папки фильтров не являются локальным состоянием: Git не игнорирует
`config\game-filters`, а локальная сборка включает его содержимое в релизный ZIP.
Перед коммитом или сборкой удалите из пользовательских фильтров приватные данные.

Если профиль уже запущен, переключение фильтра сразу обновляет временные
сопоставления `hosts`. Доменные, IP-списки и транспортные правила полностью
перечитываются winws2 только при следующем запуске стратегии или службы.
Для службы данные фильтра перед обновлением копируются в защищённый снимок в
`%ProgramData%\TrafficProfileManager\Service`.

## Универсальный транспорт

Универсальный транспорт — независимый слой, который можно включить вместе с
любой стандартной стратегией. Он использует те же режимы `Off`, `TCP`, `UDP`
и `TCP+UDP`, пресеты `Balanced` и `Extended`, но не требует отдельного игрового
фильтра или списка `ips.txt`.

В отличие от точного игрового фильтра, универсальное правило применяется ко
всем адресам на выбранных портах. Общие `lists\ips-exclude.txt` и
`lists\user-ips-exclude.txt` сохраняют приоритет. Настройка удобна для игр с
часто меняющимися адресами, однако широкий диапазон `1024-65535` увеличивает
объём перехватываемого трафика. Для начала лучше выбрать `Balanced` и известные
порты игры.

Настройка хранится в `state\universal-game-transport.json`. Файл создаётся
только после первого изменения, не входит в чистую релизную сборку и не
перезаписывается файлами обновления. Новые параметры применяются при следующем
запуске стратегии или службы.

## Структура фильтра

```text
config\game-filters\my-game\
├── filter.json
├── hosts.txt
├── domains.txt
├── ips.txt
├── domains-exclude.txt
└── ips-exclude.txt
```

### `filter.json`

```json
{
  "schemaVersion": 2,
  "id": "my-game",
  "displayName": "My Game",
  "description": "Пользовательский игровой фильтр.",
  "transport": {
    "mode": "off",
    "preset": "balanced",
    "tcpPorts": "1024-65535",
    "udpPorts": "1024-65535",
    "udpFake": "assets\\ACTIVE_GAME_UDP.bin"
  }
}
```

`id` должен совпадать с именем папки и содержать только строчные латинские
буквы, цифры, `-` или `_`.

Версия схемы `1` продолжает поддерживаться и означает выключенный транспортный
слой. Новые фильтры создаются со схемой `2`.

### Транспортный режим

Транспортный слой предназначен для игровых соединений, которые используют
неизвестные zapret2 протоколы на нестандартных портах:

- `off` — только `hosts`, домены, IP и исключения;
- `tcp` — обработка TCP на `tcpPorts`;
- `udp` — обработка UDP на `udpPorts`;
- `all` — TCP и UDP одновременно.

`tcpPorts` и `udpPorts` принимают порты и диапазоны через запятую, например:

```text
443,3074,10000-10100
```

Транспорт нельзя включить при пустом `ips.txt`. Это защищает остальные
приложения от широкого перехвата. Обработка применяется только к IP/CIDR
текущего игрового набора; его `ips-exclude.txt` и общие IP-исключения сохраняют
приоритет.

Доступны два пресета:

- `balanced` — умеренная обработка первых пакетов, рекомендуется для начала;
- `extended` — увеличенное число UDP fake и TCP sequence overlap, ближе к
  широким игровым стратегиям и потенциально сильнее влияет на совместимость.

`udpFake` — относительный путь к бинарной полезной нагрузке внутри каталога
программы. По умолчанию используется `assets\ACTIVE_GAME_UDP.bin`. Абсолютные
пути, выход за пределы программы, отсутствующий или пустой файл отклоняются.
Изменение режима, портов или пресета требует перезапуска профиля либо службы.

### `hosts.txt`

Используется обычный формат Windows `hosts`:

```text
203.0.113.10 signon.example-game.test
203.0.113.11 api.example-game.test media.example-game.test
```

В одной строке можно указать несколько имён. Маски и подстановочные символы
`*` не поддерживаются, поэтому каждое полное имя добавляется отдельно.

Записи включённых игровых фильтров объединяются с другими временными
сопоставлениями программы внутри блока:

```text
# TrafficProfileManager Mapping BEGIN
...
# TrafficProfileManager Mapping END
```

Остальная часть системного `hosts` не изменяется. При закрытии видимой
стратегии, остановке или удалении службы управляемый блок удаляется полностью.
Если два включённых фильтра назначают одному имени разные IP, запуск
останавливается с ошибкой вместо выбора случайного значения.

### `domains.txt`

Домены, которые обрабатываются выбранной стратегией:

```text
example-game.test
api.example-game.test
```

Запись базового домена обычно охватывает его поддомены по правилам hostlist
zapret2. Префикс `^` можно использовать для точного имени:

```text
^signon.example-game.test
```

### `ips.txt`

IPv4, IPv6 или CIDR-диапазоны, которые обрабатываются выбранной стратегией:

```text
203.0.113.10
198.51.100.0/24
2001:db8::10/128
```

Не добавляйте без необходимости большие диапазоны облачных провайдеров: один
диапазон может одновременно обслуживать игру и множество несвязанных программ.

### Файлы исключений

`domains-exclude.txt` и `ips-exclude.txt` имеют тот же формат, но исключают
адреса из обработки zapret2. Сопоставления из `hosts.txt` они не отменяют.

## Жизненный цикл

Включение фильтра означает, что его настройки будут использованы обычными
BAT-файлами стратегий и службой:

1. перед запуском проверяются формат фильтра и конфликты;
2. домены, IP и исключения добавляются к аргументам winws2 без копирования в
   общие пользовательские списки;
3. для включённого транспортного режима создаются отдельные IP-ограниченные
   TCP/UDP-правила и расширяется перехват нужных портов;
4. временные записи `hosts` устанавливаются после запуска профиля;
5. при закрытии окна стратегии сторож завершает winws2 и удаляет весь
   управляемый блок `hosts`;
6. для службы сопоставления очищаются при её остановке или удалении.

Само состояние `[x]` сохраняется, поэтому выбранный фильтр снова применяется
при следующем запуске профиля. Чтобы полностью отключить набор, переключите его
в состояние `[ ]`.

## Создание своего фильтра

Выберите `C` в меню Game Filters, задайте идентификатор и отображаемое имя.
Менеджер создаст все обязательные файлы с комментариями и откроет папку.

Можно также скопировать существующую папку, переименовать её и изменить `id` в
`filter.json`. Новый набор появится в меню автоматически. Некорректные файлы
отображаются с объяснением ошибки и не могут быть включены.

## Пример Marathon

Комплект содержит только временные сопоставления точек входа. Доменные и
IP-списки zapret2 оставлены пустыми, чтобы не изменять игровой трафик без
необходимости. Транспортный режим по умолчанию выключен.

Указанный адрес является сторонним шлюзом, а не официальным сервером
разработчика игры. Он может измениться или перестать отвечать. Перед включением
проверьте актуальный адрес у оператора решения и учитывайте, что сторонний
маршрут видит метаданные соединения. Проверка сертификата приложением должна
оставаться включённой.

## Ограничения

- игровой фильтр не является VPN или прокси и сам по себе не меняет внешний IP;
- `hosts` помогает только там, где приложение обращается к известному имени;
- прямые подключения игры по IP требуют `ips.txt` и подходящей стратегии;
- широкий диапазон `1024-65535` увеличивает объём перехватываемого WinDivert
  трафика, поэтому сначала используйте известные порты игры;
- если игра или другое приложение перестало подключаться, выключите
  транспортный режим либо перейдите с `extended` на `balanced`;
- серверные ограничения аккаунта или региона таким способом не устраняются;
- адреса авторизации, CDN и матчей могут различаться и меняться со временем.
