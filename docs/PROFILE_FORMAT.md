# Формат профиля

Профили трафика — JSON-документы в `config\profiles`.

## Минимальная структура

```json
{
  "name": "example-profile",
  "displayName": "Example profile",
  "order": 100,
  "description": "Краткое описание назначения варианта.",
  "interception": {
    "tcpOut": "80,443",
    "udpOut": "443"
  },
  "blobs": [
    {
      "name": "sample_tls",
      "path": "assets\\tls_clienthello_www_google_com.bin"
    }
  ],
  "rules": [
    {
      "name": "tls",
      "match": [
        "--filter-tcp=443",
        "--filter-l7=tls"
      ],
      "actions": [
        "--payload=tls_client_hello",
        "--lua-desync=multidisorder:pos=1"
      ]
    }
  ]
}
```

## Поля верхнего уровня

| Поле | Обязательно | Назначение |
| --- | --- | --- |
| `name` | Да | Стабильный ID, совпадающий с именем JSON-файла |
| `displayName` | Рекомендуется | Название в менеджере и отчётах |
| `order` | Рекомендуется | Порядок в меню и тестировании |
| `description` | Рекомендуется | Понятное описание назначения |
| `interception` | Да | Диапазоны исходящих портов WinDivert |
| `blobs` | При использовании | Именованные бинарные образцы |
| `rules` | Да | Упорядоченные группы фильтров и действий |

ID может содержать буквы, цифры, `_` и `-`. Менеджер создаёт ID в нижнем
регистре длиной до 64 символов.

## Перехват

`tcpOut` и `udpOut` содержат порты или диапазоны через запятую:

```json
{
  "tcpOut": "80,443,2053,2083,2087,2096,8443",
  "udpOut": "443,19294-19344,50000-50100"
}
```

Указывайте только необходимый трафик. Слишком широкий перехват может влиять на
посторонние приложения.

При включении транспортного режима игрового фильтра менеджер централизованно
объединяет его TCP/UDP-порты с `tcpOut` и `udpOut` выбранного профиля и добавляет
отдельные IP-ограниченные правила. Вручную дублировать игровые правила во всех
профилях не требуется.

## Blob-файлы

Имена blob используются Lua-действиями:

```json
{
  "name": "sample_stun",
  "path": "assets\\stun.bin"
}
```

```text
--lua-desync=fake:blob=sample_stun
```

Имя должно быть уникальным, путь — относительным и находиться внутри `assets`.
Абсолютные пути, `..`, точки повторного анализа (reparse point) и ссылки за
пределы `assets` отклоняются.

Префикс `tpm_game_` зарезервирован для динамических blob-файлов игрового
транспортного слоя.

## Правила

Правила передаются runtime в порядке массива. В каждом правиле используются:

- `name` — диагностическое имя;
- `scope` — необязательный селектор `targets`, `first` или `all`;
- `match` — аргументы фильтра runtime;
- `matchGroup` — ссылка на общую группу фильтров вместо `match`;
- `actions` — аргументы обработки payload и Lua.

Каждое правило задаёт ровно одно поле: `match` или `matchGroup`. Общие группы
описаны в `config\rule-groups.json` и удобны для одинаковых селекторов,
используемых несколькими профилями. При проверке профиля группа разрешается в
обычный массив аргументов; неизвестная группа или одновременное наличие двух
полей считается ошибкой.

```json
{
  "name": "service-tls",
  "scope": "first",
  "matchGroup": "discord-tls",
  "actions": ["--payload=tls_client_hello", "--lua-desync=multidisorder:pos=1"]
}
```

`rules`, `match`, `actions`, `blobs` и `interception.rawParts` должны быть
JSON-массивами. Имена правил и blob должны быть уникальными, каждый аргумент
должен быть одной непустой строкой `--...`, а выражения портов обязаны
находиться в диапазоне `1-65535`. Пути `rawParts` ограничены корнем программы и
не могут проходить через точки повторного анализа (reparse point).

Менеджер выполняет эту структурную проверку при обнаружении профиля.
Авторитетную проверку параметров выполняет `Validate Profiles.bat` через
комплектный `winws2 --dry-run`.

При установке службы проверенный профиль и его файлы копируются в защищённый
снимок. Изменение JSON-профиля после установки службы применяется только после
её переустановки.

## Создание профиля

1. Выберите **Create a custom profile** в `Manager.bat`.
2. Скопируйте наиболее близкий рабочий профиль.
3. Изменяйте по одному механизму за раз.
4. Сохраняйте отдельные правила сервисов и медиатрафика, если не тестируете их
   намеренно.
5. Выполните валидацию.
6. Проверьте видимый запуск.
7. Сравните результат через `Test Profiles.bat`.

Пользовательский профиль обнаруживается при каждом открытии меню или запуске
теста. Регистрировать его в коде менеджера не требуется.
